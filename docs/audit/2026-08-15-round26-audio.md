**与 round-10 audio-bus 的关系：** round-10（2026-08-06，见 `docs/audit/README.md:97` 与 round-13 报告）审核的是 `core/audio-bus.ts` —— SFX 总线的 WebAudio 上下文与音效播放；本次审核的是 `core/audio.ts` —— 音乐播放器本体（StreamAudioPlayer + 播放列表 + VMD 同步 + 节拍检测桥接）。两者各持独立 AudioContext（audio-bus 管 SFX，audio.ts 的 `_audioCtx` 仅服务淡入链路与节拍检测共享 source），无共享状态，不构成重复实现。

**总体结论：⚠️ 有条件通过**

测试侧质量良好：63/63 用例全绿（vitest 4.1.9，3.30s），合并干净，mock 工厂遵循项目 AGENTS 的 globalThis 约定键；`npm run check`（`tsc --noEmit && check:lint`）退出码 0，i18n parity 全对齐。生产代码无新增 `as any`/`@ts-ignore`，dispose 资源链完整，NaN/Infinity 防护到位（round-14 P2 修复已落地并有测试覆盖）。

**有条件项（2 个 P2，均未被现有测试覆盖）：**
1. `_crossfadeTo` 的 setTimeout/setInterval 无句柄追踪与取消，快速切歌/切歌途中 dispose 时残留定时器触碰已释放 player；
2. 播放列表在 `loadAudioFile` 替换源时保留已 revoke 的 blob URL 条目，且 `_playIndex` 用 URL 尾段推导曲名（blob URL 会得到 UUID 垃圾名），repeat-all / ended 自动切歌会切到失效 URL。

## 测试质量评价

**合并质量：好。** 4 文件合并为 1（568 行）是干净的同构收敛：共享样板（vi.mock 4 件套 + beforeEach/afterEach）收敛为一份，describe 按原主题分区（播放器生命周期 72-192 / 查询跳转 194-283 / 同步节拍 285-394 / 音量偏移 396-438 / 边界补充 440-524 / 播放列表 526-568），行为保持不变。头注释（1-6 行）交代合并动机与结构，审阅友好。配套 `audio-helpers.ts`（fixture 工厂）+ `audio-mocks.ts`（vi.mock 工厂）职责分离清晰，mock 工厂全部使用 globalThis 约定键，规避 hoist TDZ，完全符合项目测试卫生铁律（frontend AGENTS §2.3）。仅存两处轻微合并残留：`setVolume` 增益重复用例（P4-T3）与 volume 断言散落两处。

**断言有效性：总体有效，一处失真。** 播放状态（`m.play/pause` 调用、`isAudioPlaying`）、音量（`m.volume` 经 setter 共享状态真实断言）、同步 seek（`m.currentTime` 精确断言 22/50/0 等目标值）均真实验证 SUT 行为；`audio-helpers` 的 getter/setter 闭包使断言与 SUT 读写同一份状态，无假断言。**例外**：`syncAudioPlayback` 漂移分支用例（311-316）只断言播放态不断言 seek 结果，纠偏逻辑实为零验证（P3-T1）。

**mock 合理性：合理。** `streamAudioPlayer` mock 以 class 惰性引用规避 TDZ（亮点）；`readFileBytes` 返回最小合法 MP3 帧头供 `loadAudioFile` 流程走通；`uiState`/`config` mock 与生产模块的消费面（getter 读、setUIState 写）对齐。不足：node 环境无 `window` 使 GainNode 主路径必然降级（P3-T2），fade 行为始终测不到。

**边界覆盖：良好但存在盲区。** 覆盖了空音频（dispose 后 no-op）、重复操作（attach 幂等）、音量钳制 [0,1]、NaN/±Infinity 免疫、abort 提前返回、越界 seek、offset 负值同步等——这些是生产代码的真实防御面。**盲区**：crossfade 定时器与快速切歌并发、播放列表 blob URL revoke 后 nextTrack（P2 缺陷直接未覆盖）、`getStreamPlayer`/ended 自动切歌/`clearAudio` 后列表状态。无 `it.skip`/`it.only`/`xit`。

**验证记录：** `cd frontend && npm run test -- src/__tests__/audio.test.ts` → 63/63 通过（vitest 4.1.9，3.30s；stderr 中 `[audio] playAudio Error: autoplay blocked` 等为生产 `safeCallAsync` 对刻意触发 rejection 的 logWarn，属预期路径）；`npm run check`（`tsc --noEmit && check:lint`）退出码 0。
