## 二、亮点

- **测试精确复刻真实跨桥文本**：`wailsErr()` helper（`goerr.test.ts:25-28`）构造 `"Binding call failed: failed to call binding: <msg>\n@@GOERR@@<json>"`，与 ADR-117 §2.6 证据链（Wails v3 `WrapBindingCallFailedErrorf` 包裹 + 纯文本 stringify）逐字一致，断言的是端到端真实路径而非 mock 简化。
- **断言真实有效**：6 个用例全部为「构造信封 → 调 `translateGoError` → 断言最终翻译文本」，code 提取、params 占位替换（`{name}`→`Blender`/`MikuMikuDance`）、语言切换（`setLang('en')` 后断言英文）均为真实执行，无浅层断言。
- **未知 code 回退链被真实命中**：用例 4（`goerr.test.ts:59-63`）触发 `t()` 缺失 key 告警 `[i18n] missing key "goerr.software.totallyUnknown" ... (typo?)`（测试运行 stderr 可证），证明「t() 返回 key 本身 → 回退信封内中文 msg」分支走的是真实代码路径，非摆设。
- **测试环境适配正确**：按 `[doc:perf]` 语言包运行时加载设计，`beforeAll` 直接预填 `bundles` 缓存（`goerr.test.ts:18-21`）；RAF polyfill 带注释说明来源（`locale.setLang → scheduleRefresh`，`goerr.test.ts:12-15`）；`afterEach` 复位语言状态（`goerr.test.ts:31-33`），用例间无语言泄漏。符合 frontend/AGENTS.md §2.3 测试卫生铁律。
- **生产代码异常路径清晰**：`goerr.ts:27-44` 单一路径——`lastIndexOf` 提取哨兵（前缀包裹文本被忽略，`goerr.ts:21-23` 注释说明设计意图）→ `try/catch` 包裹 `JSON.parse` → `env.code` 守卫 → `t()` 翻译 → `translated !== key` 判定回退。纯函数、无资源、无状态、无并发面。

## 三、风险表

| 严重度 | 文件 | 位置 | 观察 | 改进建议 |
|--------|------|------|------|----------|
| 🟡 P3 | `frontend/src/core/i18n/goerr.ts` | 31-39 | 信封缺 `code`（如 `@@GOERR@@{"msg":"x"}`）时 `env && env.code` 为 false，直接 `return raw`——raw 含 `Binding call failed: ...\n@@GOERR@@<json>`，用户会看到哨兵与 JSON 噪音。Go 端 `UserError.Code` 必填保证正常路径不触发，但属防御性边角。round-15 仅关注「code 缺失时 t('goerr.undefined') 静默回退」并判定守卫可接受，未覆盖此「返回含哨兵 raw」的具体行为 | 缺 code 分支改返回剥离哨兵后的文本（`env.msg ?? raw.slice(0, idx).trim()` 或直接 `env.msg ?? raw`），并在测试中补该用例 |
| 🟡 P3 | `frontend/src/__tests__/goerr.test.ts` | 全文件 | 畸形 JSON 信封分支未覆盖：生产代码 `goerr.ts:40-42` 的 `catch`（哨兵在但 JSON 非法）是真实防御路径，前端测试 0 覆盖；而 Go 侧 `internal/i18nerr/errors_test.go:43` 恰恰覆盖了 `"has marker but bad json @@GOERR@@{not json"`——前后端测试不对称 | 补 1 用例：`wailsErr` 变体注入非法 JSON（如 `@@GOERR@@{not json`），断言回退原始文本。可参考 Go 侧同名用例对齐契约 |

## 四、测试质量评价

**有效性**：✅ 高。6 个用例覆盖 ADR-117 的核心行为矩阵——翻译命中（zh-CN/en 双语言 + 参数替换）、未翻译回退（未知 code → 信封内 msg）、无信封透传（旧式文本）、非 Error 输入（原始字符串）。`wailsErr` helper 严格对齐真实 Wails v3 跨桥格式，断言全为最终用户可见文本，无 mock 失真。

**边界覆盖**：✅ 主要路径齐全；⚠️ 两处缺口——① 畸形 JSON（哨兵在、JSON 非法）的 `catch` 分支前端 0 覆盖（Go 侧已覆盖，前后端不对称）；② 信封缺 `code` 的分支 0 覆盖（且该分支行为本身有 P3 瑕疵，见风险表）。次要缺口：`params=undefined` 的 `??` 兜底、toText 的 `{message}`/`String(e)` 分支、ja/ko/zh-TW 语言。

**跳过测试**：✅ 无 `.skip` / `.only`，6 用例全部真实执行。

**测试自身卫生**：✅ 语言状态 `afterEach` 复位、`bundles` 预填符合运行时加载设计、RAF polyfill 有来源注释、无 `window` 污染（符合 frontend/AGENTS.md §2.3 铁律）。唯一小瑕疵：RAF polyfill 用 `as unknown as typeof globalThis.requestAnimationFrame` 断言（`goerr.test.ts:14`），属测试代码中的类型收窄，有注释说明，可接受。
