## 1. Codex CLI v0.145.0：多 Agent V2 转正 + 一键迁移 Claude Code/Cursor 配置

**事件**：OpenAI 于 7 月 21 日推送 Codex CLI rust-v0.145.0，两项变化值得关注：

- **多 Agent V2 从预览毕业为稳定版**：根会话可派生可配置子 Agent（独立模型、推理级别、并发与沙箱配置），新增 `spawn_agent` / `send_input` / `resume_agent` / `wait_agent` / `close_agent` 原语，并恢复角色系统与 Agent 导航，缓解早期"五个不沟通的承包商"式互相覆盖/上下文丢失问题。默认关闭。
- **`/import` 一键迁移**：可把 Cursor 与 Claude Code 的设置、MCP 服务器、插件、会话、命令、项目级记忆一次性搬入 Codex（插件命令转 Codex skills）。迁移单向，本地执行，最多 50 个近 30 天会话。

**值得关注的原因**：
- 多 Agent 从"概念热点"变成"可用基建"，意味着 AI Coding 的并发编排不再需要外部编排脚本。
- `/import` 把开发者换工具的沉没成本（.cursorrules、MCP 列表、数百轮会话上下文）归零，本质是基础设施级抢占——对正在选型或维护多工具链的团队，迁移摩擦大幅降低。

## 2. Coding Agent 安全集体爆发：Friendly Fire / Ghostcommit / HalluSquatting 同属"auto-mode 攻击面"

**事件**：7 月多条独立披露指向同一根因——**Agent 在 auto/免确认模式下无法区分"数据"与"指令"**：

- **Friendly Fire**（AI Now Institute，7/8）：在第三方仓库 README 里埋"运行安全检查脚本"的指令，Claude Code / Codex 在 auto-mode 安全审查时自动执行恶意二进制，实现主机 RCE。Claude Code 2.1.116–2.1.199、Codex 0.142.4 均 confirmed；厂商视为"预期行为"，无补丁。
- **Ghostcommit**（ASSET Research Group）：把注入指令藏进 PNG，被引用自 `AGENTS` 约定文件；多数 AI 审查器默认不扫图片，PR 干净合入，后续会话触发读 `.env` 并外泄。Cursor / Antigravity 在 Sonnet、Gemini、GPT-5.5 下泄露，Claude Code 全模型拒绝。
- **HalluSquatting**：Agent 幻觉出不存在的仓库名，攻击者预先抢注同名陷阱仓库，任意开启 `--skip-permissions` / `--yolo` 的 Agent 自投罗网。影响 Cursor、Copilot、Windsurf 等 9 款工具。

**值得关注的原因**：
- 三者共同根条件是"Agent 有免确认执行权限"。安全结论很明确：**auto-mode 只适用于你自己拥有且理解代码库的受信任工作流；对第三方/不可信代码做审查时必须隔离沙箱 + 人工确认**。
- 对联邦自身（MikuMikuAR 的 AI 辅助开发流程）的直接启示：CI 中若引入 coding agent，必须禁用跨仓库命令审批继承、禁止自动安装 AI 建议的依赖、对 `.workbuddy` 约定文件做来源校验。

## 3. 上下文工程成 Coding Agent 失效主因：长上下文 ≠ 更好

**事件**：7 月社区研究集中指出，大多数 coding agent 在真实仓库失效并非模型能力问题，而是**上下文供给错误**：

- Chroma 测 18 个前沿模型随��下文变长全面退化；
- ETH Zurich 发现自动生成超长 `CLAUDE.md` 使任务成功率降约 3%、成本涨 20%+；
- Sourcegraph CodeScaleBench 显示"给对工具"比"给长上下文"更关键。

同时，**多 Agent 长期协作暴露项目记忆缺失**：关键经验锁在各自会话里。开源项目 **Deja-vu** 通过索引 Claude Code / Codex / Cursor 本地会话实现跨 Agent 检索与 handoff，提出 `AGENTS.md` / `DECISIONS.md` / `KNOWN_ISSUES.md` / `RUNBOOK.md` 四层记忆架构。

**值得关注的原因**：
- 这恰好印证了联邦的 `AGENTS.md` / `USER.md` / 项目 `MEMORY.md` 分层记忆实践方向正确——但需补强"跨会话/跨 Agent 检索"环节。
- 对 prompt/上下文设计的具体约束：约定文件宜精简、按需注入，而非堆长文本。

## 4. 清华开源 Harness VLA：具身智能从 End-to-End VLA 走向"模型 + 系统"范式

**事件**：7 月 22 日，清华大学于超教授团队联合正行创新、无问芯穹发布并开源 **Harness VLA**。核心思路：不训练更大的端到端 VLA，而是**冻结 VLA**，在其外包裹一层 Harness Layer（Agentic Planner），统一编排模型调用、任务执行与失败恢复：

- VLA 仅负责接触密集操作（抓取/放置/按压/抽屉），确定性高的移动/位姿调整交给 Analytic Primitives；
- Agentic Planner 在闭环交互中学习 Primitive 组织方式，失败自动 re-staging 重试；
- 在 LIBERO-Pro 扰动评测达 **82.4%**（对比 Pi_RLinf 50%、NVIDIA Cap-X 18.2%、Berkeley RATS 43.8%）；RoboCasa365 见任务 91.6%；RoboTwin 双臂零样本 58.4%。

**值得关注的原因**：
- 论文核心判断与 coding agent 殊途同归：**数字智能早已走过这条路**——Claude Code / Codex 都不是在 LLM 内部解决一切，而是在外面套 Harness Layer。现在这条"系统层编排"路线开始进入物理世界。
- 对具身方向的技术路线有直接借鉴价值：联邦若涉足机器人/AR 肢体控制，优先投资"调度层 + 失败恢复"而非盲目堆模型参数，ROI 更高。
