# 脚步声开关打开后静默无声

> **状态**: 🟢 已修复

**日期**: 2026-10-24（发现）／问题潜伏自 2026-08-12
**严重程度**: 🟡 P2（功能失效，但默认关闭需主动开启才暴露）
**影响范围**: `frontend/src/scene/motion/footstep.ts`（事件源选择）+ `frontend/src/scene/motion/feet-adjustment.ts`（是否在解算的可观测性）
**发现方式**: 排查 ADR-273 phase 1 迁移时留下的"脚部 enabled: false"欠账，顺链条读到消费者
**修复方案**: ADR-275 —— 判据从 `isFeetAdjustmentRunning()`（注册过）换成 `isFeetAdjustmentEnabled()`（上一帧真在解算）

---

## 问题描述

设置 → 媒体 → "启用脚步声"打开后，角色走动/动作落地没有任何脚步声。

同一设置里的"脚步声音量"滑块有效（数值被持久化），但声音从不出现。

## 根因分析

脚步声有两个可能的事件源，二选一：

1. **脚部跟随**（`frontend/src/scene/motion/feet-adjustment.ts`）——每帧解算脚 IK 贴地，检测上升沿发出 `FootLandEvent`；
2. **降级检测**（`frontend/src/scene/motion/footstep-detect-fallback.ts`，ADR-088 Phase B）——脚部跟随不可用时，直接读 IK 骨骼世界 Y 判断落地。

`startFootstep()` 用 `isFeetAdjustmentRunning()` 决定启动哪个：

```ts
// frontend/src/scene/motion/footstep.ts:168（改前）
if (!isFeetAdjustmentRunning()) {
    startFallbackDetection(scene, callback);
}
```

而 `isFeetAdjustmentRunning()` 的实现（`frontend/src/scene/motion/feet-adjustment.ts:129`，改前）只问 observer 有没有注册：

```ts
export function isFeetAdjustmentRunning(): boolean {
    return _unregisterHandle !== null;
}
```

2026-08-12 的 `88d75986`「废弃脚部地面跟随」把每个模型的默认状态改成 `enabled: false`（`frontend/src/scene/motion/feet-adjustment.ts:405` 的门口径），但保留 `startFootstep` 之前仍无条件 `startFeetAdjustment(...)` 的调用。于是：

- 生产者：全部模型 `enabled: false` → 永不发落地事件；
- 探针：observer 注册过 → 恒 `true`；
- 消费者：认为脚部跟随在供事件 → 不启动降级检测；
- 结果：**两个源同时为零**。

## 为什么没有暴露

- **默认关闭**：`frontend/src/menus/settings-media.ts:225` 的 `get: (v) => v === true`，用户不主动打开就听不出来；
- **测试锁的是接线不是行为**：`frontend/src/__tests__/footstep.test.ts:189-193`（改前）断言"running=true 时不启动降级检测"——把 bug 写成了规格，26 个用例全绿；
- **无类型可依**：`boolean` 没有区分"已注册"与"有产出"的能力，`tsc` 无从报错。

## 修复方案

见 ADR-275：

```ts
// feet-adjustment.ts
let _anyEnabled = false;
export function isFeetAdjustmentEnabled(): boolean { return _anyEnabled; }

// footstep.ts
if (!isFeetAdjustmentEnabled()) {
    startFallbackDetection(scene, (e) => {
        if (isFeetAdjustmentEnabled()) return;
        callback(e);
    });
}
```

`_anyEnabled` 每帧刷新：有模型跨过 `enabled && intensity>0 && runtimeBones.length>0` 门即 `true`，`stopFeetAdjustment()` 复位，未跑过帧为 `false`。

## 验证

- `npx vitest run src/__tests__/footstep.test.ts src/__tests__/feet-adjustment.engine.test.ts`：56 passed。
- 回归锚点：把 `footstep.ts` 的判据改回 `isFeetAdjustmentRunning()`，3 条用例变红（"未真正启用时启动降级检测"、"注册过但无模型启用 → 仍启动降级检测"、"降级回调在脚部跟随接管后让位"）；改回即绿，文件 SHA-256 一致。
- 真机验证仍待做（需 `wails dev` + 实际模型走动）；headless 只能证明事件源已接通，不能证明音色输出（合成走 `playSfx`，被 mock）。

## 教训

1. `isXRunning()` 若答案来自注册状态，不能用于判断"有没有产出"。
2. 废弃子系统时要沿消费边走到头——生产者关掉、消费者还在问同一个探针，链路就整体静默。
3. 断言接线形状的测试会保护 bug；回归用例应在判据回退时变红。
