## 网站格式规范（VitePress）

每页 `# <功能名>.md` 以 YAML frontmatter 开头：

```yaml
---
title: 水面设置            # 页面标题（必填）
description: 舞台水面：波纹、反射、涟漪与水下过渡的一站式设置  # SEO/卡片摘要（必填）
outline: [2, 3]            # 侧栏目录深度：显示 ## 与 ###
prev: false                # 关闭上一篇导航（可选，列表页适用）
next: false
---
```

**命名与目录约定**：
- 文件名 `kebab-case`（`env-water.md` / `import-model.md`），与菜单路由语义对应
- 图片放同目录 `img/<page>-<n>.png`（如 `img/env-water-1.png`），正文用 `![描述](../guide/img/env-water-1.png)`——VitePress 会做资源内联，勿用绝对路径
- 多页时新增 `docs/guide/` 根列表页即自动进 VitePress 侧栏（`sidebar` 用 autogenerated）

**标题层级**：`#` 页题 → `##` 五段骨架 → `###` 细分步骤/参数分组，不跳级。

## 写作模板（每页统一骨架）

```
---
title: <功能名>
description: <一句话摘要>
---

# <功能名>

## 它能做什么          → 一段话，用户能达成什么效果
## 打开方式            → 菜单路径 / 快捷键 / 入口按钮
## 操作步骤            → 编号步骤 + 截图（截图标号如 env-water-1.png）
## 常见问题            → FAQ（可选）
## 相关功能            → 用户视角的横向导航（如「地面设置 / 天空设置」），指其他 guide 页
```

**铁律**：
- 菜单树、API 签名只做**链接跳转**（指向 `menu-map.md` / `function-map.md` / knowledge 卡），不手写复述——避免双写漂移。
- **guide 页不面向开发者**：尾部最多留一个「进阶」入口（指向 knowledge 卡），不罗列内部文档链接；「相关链接」一律改为「相关功能」。
- **截图优先**：能配图的操作步骤必须配图（VitePress 渲染后图片即所见即所得），截图命名见上。
