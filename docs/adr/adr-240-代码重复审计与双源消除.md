## 1. 背景：审计发现三类可处置项

按 AGENTS.md「显著重复」标准（相似逻辑 ≥2 文件出现应抽取，UI builder 纯布局除外）全仓盘查：

| 级别 | 位置 | 事实（实测） |
|------|------|-------------|
| 🔴 P1 | `frontend/src/_reach*.cjs` ×7、`base_export/`（7.6M） | 一次性探查脚本 + 误导出目录，全部未跟踪，迟早误提交 |
| 🟠 P2 | `menus/scene-menu.ts:39` vs `core/image.ts:13` | 私有 `canvasToBase64` 与 ADR-191 下沉的零依赖叶**逐字等价**（diff 仅 FileReader 分支 if/else vs 三元风格漂移）——双源隐患：单侧修复即分叉 |
| 🟡 P3 | `scene/env/env.ts:108` `applyWindToParticles` | 与 `env-particles.ts:826` 真实实现（`ps: ParticleSystem`）**同名空壳**（`_wind: {x,y,z}`），正文为空——实测无任何外部调用，纯误导性占位 |
| 🟢 P4 | `menus/model-preset.ts:353` vs `menus/preset-list-viewer.ts:156` 双 `buildPresetListLevel` | 同名不同义（无参专用 vs 泛型通用），导出名冲突易误用 |
| ✅ 合法 | `env.ts` 门面、`camera.ts`↔`camera-state.ts`、`lipsync-bridge.ts`↔`perception.ts`、`core/path.ts`↔`library/library-path.ts`（`computeLibraryRef` 包装器）、测试 mock 重名 | 均为刻意分层/适配器（注释明示），**不合并**——保持现状 |

非重复澄清：`canUndo`/`buildLevel`/`getScene`/setter 双份（`setCameraControl`/`setFov`/`setLipSyncEnabled` 等）均为同名不同义或状态层/行为层分层，非逻辑重复，不动。

## 2. 决策

1. **P1 清理**：删除 `_reach*.cjs` ×7 与 `base_export/`；`.gitignore` 加 `base_export`，防再犯。
2. **P2 双源消除**：`scene-menu.ts` 删除私有 `canvasToBase64`，改 `import { canvasToBase64 } from '@/core/image'`（`ar-camera.ts`/`thumbnail-capture.ts` 已如此导入，签名一致，行为不变）。
3. **P3 空壳删除**：删除 `env.ts:108` 的 `applyWindToParticles` 空壳——无调用方，且与 `env-particles.ts` 真实实现重名构成陷阱（从 `@/scene/env` 导入会拿到空壳）；真实风力路径在 `env-particles.ts` 内部自洽。
4. **P4 暂缓**：`buildPresetListLevel` 改名（如 `buildModelPresetLevel`）收益低、波及两文件引用，记录为后续可选，本次不执行。
