# MikuMikuAR 联邦 — 全模块系统审核计划

> 审核目标：对联邦全栈进行系统性健康度审计，识别代码质量、性能、安全性、可维护性风险，输出可执行的修复优先级清单。

---

| 层级 | 模块 | 文件数 | 子代理 | 预计工时 |

| **前端** | `core/` 核心基础设施 | ~184 .ts | 前端架构师 | 2h |

| **后端** | `internal/app/` Go 核心 | ~30 .go | Go 后端专家 | 1.5h |
| **后端** | `internal/app/llm/` LLM 客户端 | ~3 .go | 安全审核员 | 0.5h |

## 二、各模块审核重点

### 2.1 `core/` — 核心基础设施

| 维度 | 审核要点 | 检查方法 |
|------|----------|----------|
| **类型安全** | `as any` / `@ts-ignore` 数量；Signal 类型是否完整 | `grep -rn 'as any\|@ts-ignore' frontend/src/core/` |
| **资源生命周期** | 每个 `new` 对象有对应 `dispose()`；Observer 在 dispose 时移除 | `grep -rn 'new \|\.dispose\|ObserverHandle'` |
| **状态流** | `envState` 写入点是否集中；是否存在"幽灵路径" | `grep -rn 'setState\|setEnvState\|= envState\.'` |
| **异常处理** | 无静默吞错 `catch{}`；Promise 链有错误处理 | `grep -rn 'catch\s*{\s*}'` |
| **并发安全** | `_loading`/`_pending` 标志；快速点击 3 次是否安全 | 代码审查 |
| **后端适配器** | ADR-177 双实现（Browser/Go）是否一致 | 对比两个 adapter 的接口覆盖 |
| **AI 子系统** | SSE 流式解析、工具调用累积、连接测试 | 审查 `core/ai/` 16 文件 |

### 2.2 `scene/` — 3D 场景引擎

| 维度 | 审核要点 | 检查方法 |
|------|----------|----------|
| **模型管理** | `model-manager.ts` (49KB) 是否过度膨胀；加载/卸载生命周期 | 代码审查 |
| **场景序列化** | `scene-serialize.ts` (69KB) 往返一致性；ADR-246 显式字段原则 | 审查 + 测试 |
| **相机系统** | 5 种相机模式状态切换是否安全；ADR-100 双轴控制 | 代码审查 |
| **环境系统** | `env/` 24+ 文件是否职责单一；ADR-237/239 超限拆分效果 | 代码审查 |
| **物理桥接** | WASM Bullet 桥接异常处理；虚拟裙骨 ADR-084 状态 | 代码审查 |
| **渲染管线** | `renderer.ts` (43KB) 质量档位切换；灯光系统 | 代码审查 |
| **感知层** | ADR-166 per-model 隔离；多角色呼吸/眨眼/视线 | 代码审查 |
| **AR 模块** | ADR-109 遗留项；WebXR 兼容性 | 代码审查 |

### 2.3 `menus/` — 声明式菜单系统

| 维度 | 审核要点 | 检查方法 |
|------|----------|----------|
| **Schema 一致性** | ADR-093 声明式 Schema 是否被所有 57 面板遵守 | 审查 `menu-schema.ts` |
| **资源释放** | ADR-252 `disposeMenuWrapper` 零调用问题 | 审查 `menu.ts` (55KB) |
| **菜单栈** | 菜单栈管理是否安全；嵌套深度是否合理 | 代码审查 |
| **设置页** | 7 个子页是否职责清晰；配置持久化链路 | 代码审查 |
| **广场模块** | 下载管理、创作者、缩略图 | 代码审查 |

### 2.4 `motion-algos/` — 动作算法层

| 维度 | 审核要点 | 检查方法 |
|------|----------|----------|
| **纯算法** | 是否零 Babylon 依赖（ADR-242 要求） | `grep -rn 'babylon\|Babylon' frontend/src/motion-algos/` |
| **VMD 写入** | Shift-JIS 编码正确性；二进制格式合规 | 代码审查 |
| **节拍检测** | Web Audio API 使用是否安全 | 代码审查 |
| **程序化动作** | 骨骼层级（trunk/limbs/emotion）是否职责清晰 | 代码审查 |

### 2.5 `__tests__/` — 测试套件

| 维度 | 审核要点 | 检查方法 |
|------|----------|----------|

| **Mock 质量** | Babylon mock 是否覆盖关键 API | 审查 `mocks/` |
| **Contract 测试** | Wails 绑定契约测试是否通过 | `npm run test -- src/__tests__/bindings/` |
| **E2E** | Playwright 测试是否覆盖关键路径 | `npm run test:e2e` |
| **测试稳定性** | 是否存在 flaky test | 审查测试代码 |

### 2.6 `internal/app/` — Go 后端核心

| 维度 | 审核要点 | 检查方法 |

| **配置合并** | ADR-253 `mergeUIState`/`mergeEnvState` 零值覆盖 | 审查 `config.go` |

| **HTTP 服务器** | 127.0.0.1 绑定；basename 兜底查找 | 审查 `httpserver.go` |

| **LLM 集成** | AIKey 不暴露给前端；流式解析安全 | 审查 `ai_binding.go` |
| **原子写入** | 所有文件写入是否使用 tmp+rename | 审查各 `*preset.go` |
| **优雅关闭** | 关闭时资源是否正确释放 | 审查 `app.go` |
| **错误处理** | `safecall` 机制是否覆盖所有入口 | 审查 `safecall.go` |

## 三、子代理角色配置

### 3.1 角色定义

| 角色 | 负责模块 | 核心能力 | 审核风格 |
|------|----------|----------|----------|
| **前端架构师** | `core/` | TypeScript 架构、状态管理、事件系统、后端桥接 | 关注模块边界、依赖方向、生命周期 |
| **3D 引擎专家** | `scene/` | Babylon.js、物理引擎、渲染管线、相机系统 | 关注性能、渲染正确性、资源管理 |
| **UI 架构师** | `menus/` | 声明式 UI、菜单系统、设置页、广场 | 关注 UX 一致性、资源释放、Schema 合规 |
| **算法审核员** | `motion-algos/` | 动作算法、VMD 格式、音频处理 | 关注算法正确性、纯函数、零依赖 |
| **测试质量官** | `__tests__/` | Vitest、Playwright、覆盖率、Mock 策略 | 关注覆盖率、测试稳定性、边界覆盖 |
| **Go 后端专家** | `internal/` | Go 并发、文件 I/O、HTTP 服务、安全 | 关注并发安全、错误处理、资源泄漏 |
| **安全审核员** | `llm/` + 全局 | 输入验证、SSRF、凭证保护、CORS | 关注攻击面、凭证暴露、输入污染 |
| **工程效率官** | `scripts/` | 构建脚本、质量门禁、CI/CD | 关注门禁有效性、脚本幂等性、维护成本 |
| **文档审计员** | `docs/` | ADR、知识卡、Buglog、文档一致性 | 关注文档准确性、完整性、同步性 |
| **架构合规官** | 跨层 | 循环依赖、分层合规、类型安全、死代码 | 关注架构纪律、技术债务、全局一致性 |

### 3.2 执行策略

**并发模式**：3 子代理 × 4 轮 = 12 个审核单元（含 1 个跨层收尾）

| 轮次 | 子代理 1 | 子代理 2 | 子代理 3 |
|------|----------|----------|----------|
| **第 1 轮** | 前端架构师 → `core/` | Go 后端专家 → `internal/app/` | 3D 引擎专家 → `scene/` |
| **第 2 轮** | UI 架构师 → `menus/` | 算法审核员 → `motion-algos/` | 测试质量官 → `__tests__/` |
| **第 3 轮** | 安全审核员 → `llm/` + 全局 | 工程效率官 → `scripts/` | 文档审计员 → `docs/` |
| **第 4 轮** | 架构合规官 → 跨层审核 | — | — |
